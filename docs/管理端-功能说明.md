# 管理端功能说明

管理端是给平台工作人员用的网站，在电脑浏览器里打开。顾客不使用这个网站，门店店员日常接单也不使用这个网站。它用来建门店、上架菜品、看订单、配会员和优惠券，以及填写微信、支付、短信这些外面服务的账号。

打开后的名称是「省钱兄国际扫码点餐系统」。登录页左侧写着：多维度数据统计、用户财务消息一体化、权限与审核。工作人员登录后，左侧是菜单。能看到哪些菜单，由这个账号的角色决定。没有权限的菜单不会出现。

下面的菜单名称来自导入的数据库。如果你后来在「菜单管理」里改过名字，以你屏幕上看到的为准。导入后左侧会出现两个都叫「订单中心」的菜单，一个给平台看全部订单，一个偏门店侧处理。点进去以页面上的按钮为准。

## 登录

登录页要填账号、密码，还要看一张图片验证码。看不清就点图片换一张。验证码由服务端生成。服务端没启动时，图片是裂的，登录也会失败。

导入 `saomadiancan-gj-service/db/diancan4.0-gj.sql` 之后，管理员账号是 `admin`。密码是加密存在 `sys_user` 表里的，和 MySQL 的 root 密码不是同一个，SQL 文件里也没有明文。

## 登录之后第一眼：数据概览

左侧「数据中心」进去就是数据概览，也是登录后的首页。这里看平台现在的概况，数字来自自己的数据库。

可以按天、按月、按年筛选。页面上常见这些数字：

- **总用户数、今日新增、本月新增、本年新增**
- **今日收入、本月收入、本年收入**
- **今日接单数量**

下面分几块：

- **订单分析**：订单总金额、订单数量、到店订单数、外卖订单数、到店订单金额、外卖订单金额、退款订单数、退款金额。
- **用户分析**：总用户、手机号用户。
- **门店统计**：新增门店。
- **订单收入分析**：一张表，能看到商户名、下单用户、支付金额、创建时间。

刚导入、还没有人下单时，这些数是 0。它用来知道有没有新订单，不是在这里替顾客付款。

## 用户中心

看在点餐端注册的顾客。可以点进某一个人看资料。

有权限时还可以：

- 修改这个人的余额
- 修改账号状态，例如禁止登录
- 把他设成会员，或取消会员

这里管的是在手机或网页里注册的人。后台工作人员的登录账号在「系统管理 → 管理员列表」，不要混在一起。用户还没在用户端注册过时，这个列表里不会凭空出现顾客。

## 财务中心

查看和点餐相关的资金记录。这里看记录、核对金额。真正扣款发生在顾客付款的那一刻，不是在这个页面输入支付密码。

## 消息中心

给用户发站内消息，例如活动、订单通知。用户在点餐端「消息中心」里看。这不是手机短信。短信要走「系统配置」里的短信服务商。

有权限时可以查看，也可以推送。

## 首页装修

决定用户端首页的轮播图：图片、标题，以及点下去跳到哪个页面。改完保存后，用户下次打开首页才会变。库里没图时，用户端首页轮播是空的，每日任务和积分商城那两张卡片仍然在。

## 商品管理

下面三个子菜单：

### 商品中心

上架、修改、下架菜品。名称、图片、价格、所属分类、规格，都在这里维护。用户端菜单读的就是这些数据。菜品还有多语言名称时，要配合「国际化配置」，否则切换语言后名字对不上。

### 商品分类

菜单左侧的分类，例如主食、饮品。用户端下单页左边那一列，来自这里。

### 商品规格

例如大小、甜度、温度。顾客点加号时弹出的规格，来自这里。没有规格的菜，可以直接按单价加入购物车。

## 门店中心

查看、新增、编辑门店。一家门店一般包括店名、地址、经纬度、营业时间、门头或轮播图、是否上架。用户端「附近门店」读的就是这些数据。门店下架后，顾客再选这家店会看到已下架的提示，不能正常点餐。

从门店行上还可以进这些操作（账号有权限时才看得到按钮）：

- **桌码管理**：添加、修改、删除桌号。到店堂食扫桌码用的是这里。
- **用餐管理**：看店里正在吃的单。
- **收款码**：看这家店的收款码。
- **退款**：对允许退款的单做退款记录。

## 商铺中心

和门店资料相关的另一套列表，同样可以查看、添加、修改、删除，也可以维护这家店的商品分类、商品规格，以及退款。导入后的菜单里，它和「门店中心」是两项。你后来如果只想留一个入口，在「菜单管理」里调整即可。

## 订单中心

查看顾客已经下的单。可以按权限做这些事：

- 查看详情
- **取餐**：把到店单往前推进一步
- **结账**：处理店内用餐的结账
- **退款**、**商品退款**
- 修改订单上允许改的内容

订单在页面上对应顾客看到的状态：待支付、待接单、制作中、待取餐、配送中、已完成、已取消。

真正扣款发生在用户付款的那一刻。这个页面是事后查看和处理。点退款是记下这笔要退的处理，并按当时的支付方式走后续。微信或 PayPal 付的，要当时的密钥仍然有效，才可能原路退回。退回钱包时，加的是这个人在本平台的余额。

## 另外一组商品和桌位菜单

导入脚本里还有一组直接放在左侧的菜单，方便按店查看：

- **商品列表**
- **商品分类**
- **商品规格**
- **桌码管理**
- **用餐管理**
- **收入统计**
- **收银台数据**

收入统计看门店做单产生的收入。收银台数据看店里收银台记下的金额。用户端、商家端首页上的收益数字，和这里是同一套账。

## 优惠券管理、优惠券记录

- **优惠券管理**：创建券，设置面额、使用门槛、有效期。
- **优惠券记录**：看谁领了、用了没有。

用户端「我的优惠券」和下单时的选券，读的是这些数据。只在这里建了券，用户还要点领取，下单时才会出现在可选列表里。没达到使用门槛时，确认订单会提示用不了。

## 充值配置

配置钱包可以充值的档位。系统配置里还有一项「充值金额额度」，导入后是 `10,100,200,500`。用户在「我的钱包」里看到的可选金额，以这两处保存的结果为准。充值如果选微信、PayPal 或 Stripe，同样要密钥。

## 会员特权、会员配置

- **会员配置**：会员卖多少钱、卖哪一种时长。
- **会员特权**：开通之后用户能看到哪些说明。

用户端「超级会员」读的是这些配置。开通要付款。会员订单折扣在系统配置里，导入后是 `0.9`，也就是按九折计算。改这个数字后，下一笔订单才用新折扣。

## 国际化配置、语种配置

这是国际版和普通单语言点餐的差别所在。

- **语种配置**：系统里允许哪些语言，例如简体中文。默认语言在系统配置里，导入后是 `zh`。
- **国际化配置**：每个词在每种语言下怎么显示。按钮上的「登录」「自取」「外卖」，以及菜名、分类名，都走这里。

顾客在用户端「我的」里点地球图标切换语言后，下一次打开页面才会变成那种语言。词条没配全时，切换之后有的字是空的，或仍是中文键名。百度翻译的 appid 和密钥填上之后，服务端才可以按配置去请求翻译；两项都空时，不会自动翻译。

## 系统配置：外面那些服务的账号都在这里

这是和第三方关系最大的一页。改完要保存。用户端下次请求才会用新的值。只在用户端改文字，不会变成已经开通了支付。

导入后你可以在这一页看到这些名字。空着的，就是还没开通。

**微信**

- 微信公众号 AppId、微信公众号秘钥
- 微信小程序 AppId、微信小程序秘钥
- 微信商户号 mchId、微信商户 key
- 订单取消通知、餐品制作完成通知、订单状态通知（模板消息，空着就不会发）
- 门店端小程序 AppId、门店端小程序密钥
- 小程序是否上架、门店端是否上线

**短信**

- 短信服务商：`1` 腾讯云，`2` 阿里云，`3` 短信宝。导入后是 `3`
- 腾讯云短信 clientId、clientSecret
- 短信宝用户名、短信宝密码

三家只用开通其中一家，并把服务商数字改成那一家。只写了短信宝、用户名却是空的，手机收不到验证码。

**支付**

- PayPal：是否开启、clientId、clientSecret、环境。环境填 `live` 是正式收款，填 `sandbox` 是测试。导入后开关是「是」，密钥是空的
- Stripe：是否开启、公钥、秘钥、回调验证签名。导入后开关是「是」，密钥是空的

**图片**

- 上传方式：`1` 阿里云 OSS，`2` 本地。导入后是 `2`，图片存在运行服务端的那台电脑上
- 改成 `1` 时，还要填 Endpoint、accessKeyId、accessKeySecret、Bucket 名称、Bucket 域名。改成阿里云但密钥是空的，上传会失败

**邮箱、地图、打印、翻译**

- 网易 163 邮箱服务器（导入后是 `smtp.163.com`）、发件邮箱、端口、授权码。邮箱登录的验证码靠这个发出去
- 腾讯地图 key
- 飞鹅打印的网址、账号 USER、密钥 UKEY
- 百度翻译 appid、app_secret

**业务数字，改完就影响下一笔订单**

- 外卖送餐跑腿费：导入后是 `0`
- 外卖订单免配送费最低金额：导入后是 `20`
- 会员订单折扣：导入后是 `0.9`
- 多长时间后自动完成订单：导入后是 `1`，单位是小时
- 是否开启签到积分：导入后是「是」
- 签到周期 `3`，每日签到积分 `10`，每天增加签到积分 `10`
- 充值金额额度：`10,100,200,500`
- 是否开启获取手机号：导入后是「是」

**给顾客看的文字和图片**

- 后台服务名称：导入后是「点餐」
- H5 域名、后台管理平台域名、商户端域名
- 用户协议、隐私政策、会员服务协议、收款协议、优惠券兑换规则、推广文案
- 客服二维码、客服微信号、新用户默认头像、推广图片

协议现在是一份示例正文。正式对外使用前，换成你自己的内容再保存。

## 系统管理

管的是工作人员，不是顾客。

- **管理员列表**：谁可以登录这个后台。
- **角色管理**：这个角色能看哪些菜单。
- **菜单管理**：左侧菜单的名字和顺序。改名之后，以新名字为准。
- 如果菜单里还有字典、参数、日志、定时任务、文件上传，它们也属于系统管理：字典是下拉选项，日志是谁改过什么，定时任务是到点自动执行的工作，文件上传是后台传图片。

没有权限的人看不到对应菜单。给新同事开账号时，在这里添加，不要把他注册成一个点餐顾客。

## 管理端和数据库的关系

管理端不自己保存门店和订单。它把操作发给服务端，服务端再写入数据库 `diancan4.0-gj`。所以：

- 服务端没启动时，验证码出不来，保存也会失败。
- 管理端的接口还指向线上时，你在页面上改的是线上数据，不是你本机刚导入的那一份。
- 用户端、商家端要能看到你刚上架的菜，它们的接口地址也必须指向同一台服务端。
