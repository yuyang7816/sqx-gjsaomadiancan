# 服务端功能说明

服务端没有给顾客点的页面。它是一台一直开着的程序：手机上的点餐应用、门店应用，以及电脑上的管理后台，把登录、看菜单、下单、付款这些请求发给它。它检查这个人能不能做这件事，把结果记进数据库，需要时再去问微信、支付宝、PayPal、Stripe、短信这些外面的服务。

可以把它理解成后厨外面的总台。三个前台说的话，都由总台记账，并在需要时给外面的公司打电话。

代码在 `saomadiancan-gj-service`。启动类是 `com.sqx.SqxApplication`。端口是 **8878**，所有接口都在 `/sqx_fast` 下面。接口列表在：

```text
http://127.0.0.1:8878/sqx_fast/swagger-ui.html
```

这一页给开发和排查用，顾客不打开它。

数据库配置在 `src/main/resources/application-prod.yml`。自己电脑上用的库名是 `diancan4.0-gj`，导入文件是 `db/diancan4.0-gj.sql`。门店、商品、桌位、订单、会员、积分、钱包都记在这个库里。

`application.yml` 里 `sqx.redis.open` 是 `false`。本地默认不连 Redis。顾客和店员登录后，服务端发一张登录凭证，之后每次请求都要带上。管理端请求还会带上当前语言，用来取出对应语言的商品名和文案。

下面按「顾客点一下，服务端做了什么」「店员点一下，服务端做了什么」「管理端点一下，服务端做了什么」来写。最后说明哪些事会真的连到微信、支付和短信。

## 它为点餐的顾客做的事

这些都是顾客在手机或网页里点一下之后，由服务端完成的。

### 注册和登录

登录有两条路：邮箱，或手机号。手机号可以选国际区号。注册时要填姓名、账号、验证码和密码，邀请码可以空着。

这个邮箱或手机号第一次按规则注册时，服务端建一个顾客账号，并记下登录凭证。之后下单、看钱包、领券都要带上这张凭证。没带，服务端就当成没登录，页面会先去登录页。

邮箱验证码走的是系统配置里的网易邮箱。短信验证码走的是短信服务商。两边的账号都是空的时，验证码发不出去。

管理端登录页上的图片验证码也由服务端生成。那是给工作人员和门店管理员用的，和顾客的短信验证码不是同一个东西。

### 首页

顾客打开首页时，服务端交回这些内容：

- 轮播图：图片，以及点下去跳到哪里。没配图时，这一块是空的。
- 每日任务、积分商城用到的开关和积分规则。导入后的默认是：开启签到，每天 10 积分，签到周期 3 天，之后每天再增加 10 积分。这些数字在系统配置里，改完才变。

首页链接或小程序码里如果带了门店编号 `shopId`，用户端会自己再去打开那家店的菜单。服务端按这个编号把这家店的资料交回去。

### 选店和菜单

- 按顾客上报的经纬度，返回附近门店：店名、地址、距离、营业时间、是否上架。
- 可以按店名再查一次。
- 进入某一家店后，按这家店的编号和当前语言，返回商品分类、菜品、价格、简介、规格。
- 语言对不上时，菜名可能是空的。默认语言在系统配置里，导入后是 `zh`（简体中文）。

只看菜单不需要付款。点进购物车、去结算时，服务端才要求登录。

### 购物车和确认订单

- 把选中的菜和规格放进这家店的购物车，并记住数量。
- 确认订单时计算：菜品金额、打包费、外卖跑腿费、优惠券、会员折扣，得到实付。
- 导入后的默认：外卖跑腿费是 0，订单满 20 可免配送费，会员折扣是 0.9。这些是系统配置里的数，不是写死在页面上的。
- 优惠券不满足门槛或已过期时，服务端拒绝使用，并告诉页面原因。
- 外卖需要收货人、电话和详细地址。到店取餐用取餐号。到店堂食和桌位有关。

### 订单状态

页面上顾客能看到的主要是这些词。服务端在库里用数字记住，页面再翻译成文字：

- **待支付**：订单已生成，钱还没到。
- **待接单**：已经付款，等门店处理。
- **制作中**：门店正在做。
- **待取餐**：到店取餐已经做好，等顾客来取。
- **配送中**：外卖正在送。
- **已完成**：订单结束。外卖单上顾客可以点确认收货。
- **已取消**：订单关掉了。有的取消会显示成已取消，并带退款标记。

顾客只能看自己的订单，改不了别人的单。订单详情里还有取餐号、菜品、打包费、跑腿费、优惠券、会员折扣、实付、收货人、电话、地址、订单编号、支付方式、备注。复制订单号只是把文字复制走，不会再向微信发一次请求。

系统配置里有一项「多长时间后自动完成订单」，导入后是 1 小时。到时间后，服务端按这个小时间隔把符合条件的订单改成完成。

### 支付

顾客选定支付方式后，服务端按方式处理：

- **钱包余额**：只减数据库里的余额，并写一条流水。余额不够就拒绝。
- **微信支付**：用商户号和密钥向微信下单，把拉起支付需要的信息交回手机。微信事后访问服务端的通知地址，核对通过后才把订单改成已支付。
- **支付宝**：同一类流程。等支付宝的通知到了，才改订单状态。
- **PayPal**：按配置里的 clientId、密钥，以及环境是正式（live）还是沙盒（sandbox），生成支付地址。顾客在 PayPal 页面付完，服务端收到结果后再改订单。
- **Stripe**：用公钥、密钥和回调签名创建支付，把支付页面地址交回去。

付完钱马上关页面、通知还没到时，订单会在通知到达后再变。顾客再次打开订单，服务端按库里的最新状态返回。

导入后的配置里，「是否开启 PayPal」和「是否开启 Stripe」都是「是」，但 clientId、密钥是空的。开关开着、密钥是空的，点下去仍然付不了。

### 优惠券、会员、积分和钱包

- 领券时检查这张券还在不在、这个人领过没有。
- 下单时检查门槛和有效期。
- 会员价格和权益说明从会员配置里读出。开通会员要再走一次支付，支付成功后才把会员到期时间写上。会员折扣按下单时配置的比例计算。
- 签到：开关开着时，按周期和每日积分给这个账号加积分。
- 积分商城按积分兑换。兑换规则的说明文字也在系统配置里。
- 钱包返回余额，以及充值、消费这些流水。充值可选金额的默认是 `10,100,200,500`，在「充值金额额度」里改。

### 消息、协议和语言

- 把订单、活动一类站内消息发给指定用户，并记下已读未读。
- 《用户协议》《隐私政策》《会员服务协议》《收款协议》的正文，从系统配置里读出。导入时已经有一份示例正文，正式给别人用之前要换成你自己的。
- 商品名、分类名、按钮上的字，按当前语言从语言表里取。顾客在「我的」里切换语言后，下一次请求带上新语言。
- 在线客服的文字留在自己的服务器上。客服二维码、客服微信号也是配置项，空着时页面上就是空的。

## 它为门店做的事

店员用的是商家端，登录的是门店管理员，不是顾客账号。服务端会先确认这个账号属于哪一家店，再允许看这家店的数据。

- **首页数字**：返回这家店的本年、今日、本月收益，以及收银台的年、月、日金额；订单按制作中、待取餐、已完成、已取消计数；商品按上架中、已下架计数。
- **订单**：列出这家店的单。制作中可以点「制作完成」或「退款」。待取餐、配送中可以点「完成订单」。外卖单还可以「打印小票」。这些按钮先检查这张单是不是这家店的，再改状态。
- **打印**：打印走飞鹅云。系统配置里的飞鹅网址、账号、密钥是空的时，点打印不会真的出纸。
- **商品**：保存这家店的菜、价格、图片、上下架，以及分类和规格。顾客在这家店看到的菜，就是这里写进去的。
- **桌位**：保存桌号一类资料。到店堂食、桌码扫码用的是这份数据。
- **用餐**：店内开台、点餐、结账，记成订单。

退款会把这张单标成退款相关状态。退回钱包还是原路退回，取决于当时的支付方式和后台怎么处理。服务端不会在店员点一下之后，自动从你的银行卡把钱转走。

## 它为管理端做的事

工作人员在电脑后台点的每一个保存、退款、上下架，都是服务端在写数据库。

- **登录和权限**：检查账号、密码和图片验证码，再按角色决定左侧能看到哪些菜单、哪些按钮能点。
- **数据概览**：从订单和用户表算出总用户、今日新增、本月新增、本年新增、今日收入、本月收入、本年收入、今日接单，以及到店订单、外卖订单、退款。
- **用户**：列出在点餐端注册的人。可以改状态、改金额、设会员。后台工作人员账号在「系统管理」里，不和顾客混在同一张操作里处理。
- **门店和商铺**：保存门店资料、营业时间、上下架。可以从门店进入桌码、用餐、收款码。
- **商品、分类、规格**：保存全平台或某家店的商品。用户端菜单读的就是这些数据。
- **订单**：查看、取餐、结账、退款、商品退款。
- **优惠券**：创建券，查看谁领了、用了没有。
- **会员**：保存卖多少钱、有哪些权益说明。
- **充值配置**：保存钱包可以充的档位。
- **首页装修**：保存轮播图和跳转。
- **国际化、语种**：保存有哪些语言，以及每个按钮、每道菜在那种语言下怎么写。商品翻译可以配合百度翻译的 appid 和密钥；这两项是空的时，不会自动翻译。
- **消息**：给用户发站内消息。这不是手机短信。
- **系统配置**：保存下面「外面的服务」那一节里的全部账号。改完保存，下一次请求才用新值。
- **管理员、角色、菜单、日志**：管工作人员账号。操作日志记下谁在后台改过什么。

## 对接了哪些外面的服务

下面每一项都是服务端真的会向外发送请求的。密钥没填时，服务端会返回失败，页面上就是点了没有付款、手机没有收到短信、打印机没有出纸。

导入脚本之后的默认情况写在「刚导入时」一列。正式给顾客用之前，把空着的密钥换成你自己申请的。

| 你要做成的事 | 系统配置里的名字 | 刚导入时 | 去哪里申请 |
|---|---|---|---|
| 短信验证码 | 短信服务商：1 腾讯云，2 阿里云，3 短信宝。另外有腾讯云 clientId、clientSecret，短信宝用户名和密码 | 服务商是 3（短信宝），用户名和密码是空的 | 短信宝、腾讯云短信或阿里云短信，三家开一家即可 |
| 微信支付 | 微信公众号 AppId、公众号秘钥、小程序 AppId、小程序秘钥、微信商户号 mchId、微信商户 key | 都是空的 | 微信支付商户平台，以及微信公众平台 |
| 门店端小程序 | 门店端小程序 AppId、门店端小程序密钥、门店端是否上线 | 是否上线是「是」，AppId 和密钥是空的 | 再注册一个小程序，和顾客端分开 |
| PayPal | 是否开启、clientId、clientSecret、环境 live 或 sandbox | 开关是「是」，密钥是空的，环境也是空的 | PayPal 开发者后台 |
| Stripe | 是否开启、公钥、秘钥、回调验证签名 | 开关是「是」，三项密钥是空的 | Stripe 后台 |
| 图片放哪里 | 上传方式：1 阿里云 OSS，2 本地。OSS 还要 Endpoint、accessKeyId、accessKeySecret、Bucket 名称和域名 | 上传方式是 2，图片先存在服务器本机 | 阿里云 OSS。用本地方式时可以先不申请 |
| 邮箱验证码 | 网易 163 邮箱服务器、发件邮箱、端口、授权码 | 服务器默认 `smtp.163.com`，邮箱和授权码是空的 | 网易邮箱里打开 SMTP，并拿到授权码 |
| 地图 | 腾讯地图 key | 空的 | 腾讯位置服务。用户端工程里另外预留了 Google 地图配置 |
| 小票打印机 | 飞鹅打印网址、账号 USER、密钥 UKEY | 都是空的 | 飞鹅云打印 |
| 自动翻译 | 百度翻译 appid、app_secret | 空的 | 百度翻译开放平台 |
| 订单完成时间 | 多长时间后自动完成订单（整数小时） | 1 | 不用申请，改这个数字即可 |
| 外卖费用 | 外卖送餐跑腿费、免配送费最低金额 | 跑腿费 0，满 20 免配送费 | 不用申请 |
| 签到 | 是否开启签到积分、签到周期、每日签到积分、每天增加的积分 | 开启，周期 3，每日 10，每天增加 10 | 不用申请 |
| 会员折扣 | 会员订单折扣 | 0.9 | 不用申请 |
| 协议正文 | 用户协议、隐私政策、会员服务协议、收款协议 | 有一份示例正文 | 换成你自己的条文 |
| 客服 | 客服二维码、客服微信号 | 空的 | 用你自己的微信 |

只把程序跑起来，不会自动拥有短信条数、支付商户号或打印机。密钥填在管理端「系统配置」，由服务端去调用。只改手机页面上的字，不会变成已经开通。

## 这些记在自己的数据库里

不用申请外面的 Key，服务端和数据库就绪就能用：

- 已经导入或后台添加的门店、商品、分类、规格、轮播、桌位。
- 顾客账号、收货地址、购物车、订单状态。
- 优惠券、积分、会员标记、钱包余额和流水。
- 语言词条。默认语言是中文 `zh`。
- 管理端的管理员、角色、菜单。

下面这些看起来像外面的服务，但当前是记在自己库里的：

- 站内消息和在线客服：连自己的服务器。要有人在管理端回复，顾客那边才会有新内容。
- 复制订单号：只复制文字。
- 钱包余额付款：只减自己数据库里的余额。
